🔴 Oracle E-Business Suite: Unauthenticated RCE Under Mass Active Exploitation

🆕 CVE-2026-46817: Oracle Payments Flaw Enables Unauthenticated Takeover, 456 Attacks Recorded in 24 Hours on Honeypots

CVE-2026-46817 (CVSS 9.8) is an improper privilege management and authentication flaw in the File Transmission component of Oracle Payments, part of Oracle E-Business Suite versions 12.2.3 through 12.2.15. The bug requires no authentication and no privileges — an attacker with network access to the HTTP interface can remotely take over a vulnerable instance. Oracle patched the flaw on May 28, 2026; active exploitation began roughly four weeks later, in late June, a timeline consistent with attackers reverse-engineering the official patch to build a working exploit.

Honeypot operator Defused Cyber reported observing exploitation attempts over the weekend of June 27–28, and one tracking firm recorded 456 distinct attack hits against Oracle EBS honeypots in a single 24-hour period. Observed exploitation attempts use crafted XML DeliveryRequest payloads with the FULL_FILE_PATH parameter set to /etc/passwd — a classic local file read / path traversal probe used to confirm exploitability and exfiltrate sensitive system files before deeper compromise. Shadowserver now tracks roughly 950 internet-exposed Oracle EBS instances, with the largest concentrations in the United States and Europe.

PORTFOLIO IMPACT: Oracle E-Business Suite runs core financial, HR, and supply-chain workflows at mid-market and enterprise organizations — exactly the profile many MSP clients' larger customers or the MSPs' own back-office systems fall into. An unauthenticated, easily automated exploit against a widely deployed ERP platform is a strong, low-noise talking point for both MDR (behavioral detection of anomalous file-read/exfiltration patterns against ERP servers) and vulnerability-aware EDR conversations — patch verification alone is not sufficient four weeks after a patch ships, given how quickly reverse-engineered exploits are now reaching mass automation.

🔴 DHS Confirms Breach of Homeland Security Information Network (HSIN)

🆕 Federal Information-Sharing Platform Breached; SharePoint System Reportedly Targeted (Confirmed July 2, 2026)

The Department of Homeland Security confirmed that hackers breached the Homeland Security Information Network (HSIN), a sensitive-but-unclassified platform used by federal, state, local, and private-sector partners to share threat and operational intelligence — including support for World Cup security coordination currently underway in the US. The intrusion is believed to have occurred between late May and early June 2026 and was disclosed publicly in early July. Reporting indicates the threat actor targeted HSIN servers as well as an internal SharePoint collaboration system; DHS has not yet attributed the intrusion to a specific actor or confirmed what, if any, documents were exfiltrated. The House Homeland Security Committee has requested a formal briefing on the incident.

PORTFOLIO IMPACT: The SharePoint angle is notable in context: the July 6 briefing covered CVE-2026-45659, a SharePoint Server RCE actively exploited by Storm-2603/Warlock since at least early July, with a patch that had been available since May. While attribution and technique for the HSIN intrusion have not been confirmed to match that specific CVE, the overlap reinforces the same pattern flagged last week — on-premises SharePoint deployments are a recurring soft target, including inside organizations that should have mature patch discipline. For MSPs with any government-adjacent, critical-infrastructure, or compliance-heavy clients, this is a timely reminder to verify SharePoint patch status and review admin-tier access logging rather than treat last week's advisory as closed.

🟠 Langflow Becomes First AI Agent Platform Added to CISA KEV

🆕 CVE-2026-55255: IDOR Flaw Lets Attackers Hijack Other Users' AI Pipelines and Harvest Credentials (Added to KEV July 7, 2026)

CISA added Langflow — a widely used drag-and-drop platform for building and running AI agent pipelines, with a REST API for programmatic execution — to its Known Exploited Vulnerabilities catalog on July 7, marking the first time an AI agent development platform has appeared in KEV. The vulnerability, CVE-2026-55255, is an Insecure Direct Object Reference (IDOR) flaw: an authenticated attacker can access other users' flows by sending a crafted request containing the victim's UUID to the /api/v1/responses endpoint, exposing sensitive data processed by that flow and consuming the victim's compute resources. CISA set a remediation deadline of July 10 under Binding Operational Directive 26-04.

PORTFOLIO IMPACT: Langflow deployments typically hold cloud credentials, LLM API keys, and access to sensitive data flows — a compromise is not just a server foothold, it is a credential-and-compute harvesting opportunity tied directly to an organization's AI infrastructure. This is the second AI-infrastructure-adjacent threat item in two briefings (following the Avalon/CrownX AI-assisted malware framework covered July 6), reinforcing that AI tooling — both attacker-side and defender-side — is now a standing category worth tracking, not a one-off story. For any client experimenting with internal AI agent pipelines (a growing segment among MSP customers), this is a concrete, dated example of what "secure your AI infrastructure" needs to mean in practice.

🟡 "Bad Epoll" Linux Kernel Privilege Escalation — PoC Released, Reaches Android

🆕 CVE-2026-46242: 99%-Reliable Use-After-Free Grants Root on Linux Servers, Desktops, and Android

Researcher Jaeyoung Chung published a working proof-of-concept for "Bad Epoll" (CVE-2026-46242), a use-after-free race condition in the Linux kernel's epoll subsystem — a core I/O multiplexing facility used extensively by nginx, Apache, Node.js, Python asyncio, database engines, and Android's event-loop infrastructure. Two separate race conditions were introduced by a single 2023 kernel commit; one was already reported by Anthropic's Mythos research effort as CVE-2026-43074, and Bad Epoll is the second, independently discovered flaw from the same root cause. The race window is only about six CPU instructions wide, but the published exploit reliably widens it via a non-crashing retry loop, achieving a 99% success rate escalating an unprivileged local user to root. The bug affects Linux kernel versions 5.10 through 6.11 and reaches Android devices through the same shared kernel code. It was reported privately in February, patched upstream April 24, and disclosed publicly May 30 — meaning the fix predates public disclosure by five weeks, and there is no confirmed in-the-wild exploitation to date.

PORTFOLIO IMPACT: No confirmed active exploitation lowers urgency relative to the Oracle EBS and Langflow items above, but a 99%-reliable, publicly available local-root PoC against a kernel version range still common in production (5.10–6.11 spans most current LTS Linux distributions and a large share of deployed Android) is the kind of bug that gets folded into post-exploitation toolkits quickly once initial access is achieved by other means. Relevant to any client running Linux servers or Android fleets — patch verification against kernel 6.12+ or the backported fix is the concrete action item.

🟡 Watchlist: Ransomware Enforcement & Ecosystem Notes

🟡 Ransomware Ecosystem Law Enforcement Actions — BlackCat/ALPHV Negotiator Sentenced, Ryuk Conspirator Pleads Guilty
🏷 US & International Law Enforcement  |  📅 July 8–10, 2026
Angelo Martino, a former ransomware negotiator who assisted the BlackCat/ALPHV group, was sentenced to 70 months in prison on July 10. Separately, Karen Serobovich Vardanyan, a 34-year-old Armenian national, pleaded guilty to conspiracy and computer fraud charges for his role in Ryuk ransomware attacks that netted accomplices more than $15 million in ransom payments. These actions arrive alongside continued 2026 ransomware-ecosystem trend data worth noting for context: the median time between initial-access-broker handoff and ransomware deployment has collapsed to roughly 22 seconds (down from over 8 hours in 2022), and "EDR killer" tooling — deliberately disabling or blinding endpoint defenses before payload execution — is now considered a standard component of ransomware playbooks rather than an advanced technique. PORTFOLIO IMPACT: Law enforcement pressure on the negotiation and laundering layer of the ransomware economy is a slow but real disruption lever, though it lags the speed of automated access-to-encryption pipelines by a wide margin. The 22-second handoff statistic and normalized use of EDR-killer tooling are useful, citable data points for MDR conversations emphasizing detection speed and tamper-resistant telemetry over signature-based defenses.

📌 Strategic Context: Patch-Lag Exploitation and AI Infrastructure Risk Are Now Recurring Themes

Two threads carry over directly from last week. First, patch-lag exploitation: Oracle EBS (patched May 28, exploited late June) joins SharePoint RCE (patched May, exploited by early July) as the second consecutive week where the most severe active-exploitation story is a known, already-patched bug rather than a novel zero-day — the operative risk continues to be the gap between patch availability and patch application, not undiscovered vulnerabilities. Second, AI infrastructure as an emerging attack surface: Langflow's KEV addition follows directly on last week's Avalon/CrownX malware framework story, and both point to the same conclusion — AI tooling, whether an agent development platform or an AI-assisted malware framework, is now a live category on both the attacker and defender side rather than a speculative future risk. The DHS HSIN breach, while less technically detailed than the other items, reinforces that even federal-tier information-sharing infrastructure is not immune to the same patch-lag and legacy-system exposure patterns seen across the MSP/SMB base this portfolio serves. For MDR and vulnerability-aware EDR conversations, the consistent message across both this week and last is: assume a meaningful population of clients are running unpatched, internet-facing enterprise software at any given time, and design detection and response around that assumption rather than around patch compliance alone.
